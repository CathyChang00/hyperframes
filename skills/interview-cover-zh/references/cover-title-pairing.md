# 封面主标题、副标题与发布标题的互补关系

用于 Cathy 的口播视频和真人访谈包装：解读或生成封面主副标题与图片外发布标题。这里的“正文 title”指发布页标题栏，不是 description 正文，也不是视频内字幕或章节标题。只换色、改字号或移动人物时，不借此重写已批准文案。当前明确选择优先于历史样本。

学习对象是封面与发布标题之间的关系，不是 Cathy 的口播句式、语速或表演。做这种风格研究无需转写、回听整段视频；生成某一期标题时则复用已有成片稿核对承诺，只有具体事实缺依据时才定向查对应片段。

## 一组文案，三个位置

先区分封面主标题、封面副标题、图片外的帖子标题；底部 `品牌 Interview | 嘉宾` 是身份识别，不是第四条标题。主副标题由信息作用判断，不把位置最高的 Logo 或采访身份条自动当 hook。

封面是最重要的 hook，先独立成立，再谈它与发布标题怎么搭配。遮住帖子标题后，封面仍应给人一个具体的观看理由：有兴趣知道答案、想理解反常选择、想学一个方法，或想知道某个结果怎样发生。新写时优先“主标题抛钩子，副标题给解答或答案线索”；判断、数字结果、人物选择也能直接成为钩子，不要求必须写成问号。不要上下都卖关子，也不要把下面写成“答案在视频里”。已定稿封面作为约束，不为提升 hook 擅自改写。

帖子标题应再增加一项有用信息：例如“人力有限”的条件、方法的名字、人物做了什么、某个反常选择的背景，或把封面中的具体结果放回行业问题。它不一定排在封面文字下面，也不必直接给完整答案；这里的上下是阅读逻辑，现有版式和平台位置仍按当前采用版。

问答方向可以反过来，封面的钩子优先级不变：封面先给一个有吸引力的判断或机制，帖子标题再交代触发它的事件或问题；也可以封面提问，帖子标题给具体方法线索。不能将这条灵活性理解为“把强钩子挪出封面”。采访身份条、现场投影和背景截图各有原本作用，不自动当作作者设计的主副标题。

三处不必完全没有共同词。公司、人物、AI/GTM 等识别词可以重复，让帖子标题脱离封面仍能看懂；需要去掉的是重复命题，不是机械降低相同字符的比例。换同义词不算补充信息。

## 可选互补方式

| 第一层钩子           | 下一层提供的新信息   | 发布标题还可以补什么                 |
| -------------------- | -------------------- | ------------------------------------ |
| 一个具体问题         | 明确判断或方法线索   | 适用人群、资源限制、场景             |
| 一项数字结果         | 如何实现的机制或路径 | 公司、阶段或完整话题                 |
| 一个反直觉观点       | 可指认的例子或动作   | 案例名称、人物选择                   |
| 值得关注的身份或经历 | 与身份反差明显的行为 | 当时的背景、他人建议、尚未解释的原因 |

这些是选择，不是每期都执行的固定句式。同一素材先找最强且有依据的事实，再选分工；不为了填三层虚构收益、补数字或制造因果。原文说“话题度”不能擅自改成独立用户或付费转化，模型数量不能改成用户数，个人经验不能改成普遍规律。

Cathy 的常见措辞是具体角色、品牌与动作，允许“薅走”“撬动”“才意识到”等口语，以及 AI、Startup、GTM、Pivot 等中英混用；使用哪个词取决于本期事实与当前语气。表情不是必填，旧的 AI 二创标题也不能直接套成真人访谈事实。

## 写作与复核

### 英文封面已定后，自动补齐发布标题

1. 绑定最终成片及其已核对稿，而不是未剪原片。用户举的“40 分钟剪到 20 分钟”是工作场景示例，不是强制时长；发布标题的承诺必须在最后保留的内容中。
2. 锁定用户确认的英文封面标题及主副层关系。要求直译时，中文忠实对应原意，只做必要语序处理；不加原文没有的数字、完成状态、情绪或另一套选题，不重开封面候选。
3. 在内部写清两件事：封面已经让观众知道什么；看完封面还自然想知道什么。后者应能由本期的判断、案例、条件、行动或转折接住。
4. 从可兑现的缺口里选择一个生成发布标题。自问自答、对比、补充背景都可用，不能为了不同而换到无关主题。标题的任务是完成这组观看理由，不是概括整期所有章节。
5. 默认内部比较候选，只交一个最贴合的推荐标题；最多附一句它补了什么。用户明确要多个选项时再给，不要求用户先挑角度、先自己想标题。15–20字、5个候选等以当次要求为准，不继承为永久规格。

### 怎样判断真的互补

自问自答不是一个问号加一句“深度解析”，而是问题能对应到判断、方法或答案线索。对比不是凭空对立，而是观众通常会怎么选与嘉宾实际选择、预期用途与真实用途、身份与行为之间有材料支持的差异。互补也可以不构成字面问答：封面讲结果，发布标题补触发事件；封面给具体动作，发布标题点明它解决的行业问题。

先检查遮住发布标题时封面是否有观看理由，再检查加回发布标题后是否多知道一件相关的事。若两处只换了近义词，是重复；若新增信息和封面不接，是跑题；若下方给的是问题的改写而非线索，是连续卖关子。既不要求逐词零重合，也不把封面里最有辨识度的关键词全部删掉。

先核对当前封面文字与已有可靠材料。用户要整组时，按“封面主标题／封面副标题／发布标题”一起展示；用户只要发布标题时，内部仍对照整组，但只交付所需项。无独立副标题的封面不要按换行硬拆。不要分别生成三份互不相干的 slogan。

封面内主副标题两层够用时，不为视觉层级再硬加一行；这不等于省略用户要求的发布标题。用户明确要主标题、副标题、发布标题时，三项都交付。每层围绕同一个观看理由：下一层应接得住上一层，不能为了信息量突然换话题。“更具体”也不等于“越写越长”；缩略图应能读到一个主要钩子和一个清楚的补充。

交付前连读一次：第一层让观众想知道什么？第二层实际回答或补充了什么？帖子标题新增了哪个条件、动作或角度？删掉第二层后如果信息几乎不变，就是重复；三层读完若只能记住品牌和身份，通常还缺内容。答案与钩子要能在节目中兑现，不将页面措辞直接当作独立核验过的事实。

视觉层级支持阅读顺序：主要钩子优先可读，副标题可较小但不能在手机缩略图里消失；强调色只标需要注意的动作、结果或关键词。学习信息关系不等于复用样本的黄条、黑底、字体或坐标，当前采用的自然照片版和平台安全区继续有效。

## 从已保存的视频样本选关系，不总拿最新一期作解释

扩展复核基于 243 条去重笔记中的全部 98 条视频记录：97 张封面可读取，1 张缺图；只对照封面与发布标题，没有播放全部视频。完整核对表留在工作项目；可复用的 24 组案例及 2 组边界案例集中在[视频标题案例库](video-title-casebook.md)，包括 Cluely、Notion、Comfy、Fish Audio、Cursor、融资庆祝、办活动、收购、产品实测等。Scott 只是一种人物故事型案例。

先按封面已承担的信息选择案例库中的相关段落：

| 已定封面在做什么       | 发布标题优先寻找的增量                 | 案例库对应位置                  |
| ---------------------- | -------------------------------------- | ------------------------------- |
| 提问并已经给出一个答案 | 让答案成立的阶段、限制、人物选择       | 1：GTM、Cluely、融资庆祝        |
| 给具体结果或机制       | 行业问题、另一种有区别的指标、方法名称 | 2：Comfy、Fish Audio、Cursor    |
| 给鲜明判断或个人事件   | 触发该判断的经历，或该事件说明的机制   | 3：Equity、acqui-hire、Lovable  |
| 讲一个让人意外的动作   | 受众、成本、资源来源、收益周期         | 4：Notion、party、Manus、超级碗 |
| 提一个范围较大的问题   | 具体条件、产品或公司案例               | 5：Voice Cursor、招聘、MCP      |
| 表达体验或产品冲突     | 测试范围、观察对象、比较条件           | 6：发布公式、Atlas、Agent       |
| 人物身份与行为存在反差 | 同一选择的另一条线索或相关结果         | 7：Corgi、Conor、Scott          |

不是所有历史配对都有足够增量。案例库第 8 节保留 Twitter 与 ABG CMO 两个边界例子：同一个主张换词、泛称“流量密码／方法论”，都不能自动算成解答。用户明确喜欢的问答、对比优先，但不把每一条强解释为问答。

向用户说明理解时，选几组和本次内容最接近、能展示不同关系的真实旧例；只引用最近讨论的 OpenClaw 不能证明已理解账号风格。案例抽样按关系与内容类型选择，不按点赞高低或最新日期选择；同主题重发与同封面改版不作为多份独立证据。历史文案是证据，不是要求以后复用这些立场、数字和经历。
