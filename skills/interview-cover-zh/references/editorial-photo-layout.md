# 自然照片版式与平台安全区

用于新建Cathy中文竖版系列，或处理“标题挪上下、名字别压点赞、照片到底”的反馈。精确复现数据在[Photon案例](photon-approved-case.md)；这里规定决策和起排尺度。

## 三个区域分别定位

标题区负责观点和信息；人物区保留同场关系；底部品牌署名负责识别。三者有独立锚点。移动标题，不移动人物或署名；调人物，不重排标题；调底部署名，先保住平台安全边界。

当前优先版式：顶部2–3行标题 → 中下部双人 → 原照片延续到底 → 平台UI上方的品牌署名。不把两人切成两个独立方框，也不为底部再造一条黑色横条。

旧版“顶部品牌行＋底部大标题”只在明确沿用那个版本时启用，其87.6%顶部占宽记录在[历史顶部品牌预设](../assets/series-header-preset.json)。当前底部署名参考宽为75.47%，不能拿87.6%直接覆盖它。

## 新封面的起排参数

以下来自本系列当前选择，是可调的起点；当前明确指令、采用的字形、画幅和平台截图优先。画幅变化按比例换算，再看实际墨迹和照片，不强行压伸。

| 部位                     |            1500×2000起点 | 比例/判断                                      |
| ------------------------ | -----------------------: | ---------------------------------------------- |
| 标题左锚点               |                      x84 | 5.6%W；自然字形的可见边缘可偏数像素            |
| 第一行可见顶边           |                     y110 | 5.5%H；不要沿用旧版离顶70px                    |
| 标题右侧留量             |               至少约84px | 5.6%W；先满足完整词和单行要求                  |
| 相邻行可见间距           |                   约60px | 3%H；Photon实测为61px/61px                     |
| 三行可见字高             |           约190/134/95px | 约9.5/6.7/4.75%H；第一行总高含英文下伸部分     |
| 最后一行至最高人物外轮廓 |              起排约170px | 8.5%H；仅作当前照片关系参照，避免碰头/帽檐     |
| 品牌署名                 | 左约19.33%W、宽约75.47%W | 先映射平台UI；不同Logo/姓名按整组等比尺度处理  |
| 品牌署名底边             |            当前样例y1796 | 89.8%H；底部约10.2%H留给照片和UI，须按截图复核 |

标题可见框采用透明层alpha≥16，正文“字面等高”可另用alpha≥128，前后不要混口径。`row_gap = next_row_top - previous_row_bottom`。锁定组内节奏后，整体下移40px就是所有标题行共同加40，不改字号、换行或间距。

完整画面的比例比单个字号更重要。短第一行不必拉满整幅；第二、三行可以接近同一右边界。三行功能和文字长度不同，不要求三个字号一样，也不把长标题缩到手机读不清。新增行用同一字体体系和基线规则，不另起装饰字体。

当前Photon中文版的排字输入为中文162/134/90px、英文204/169/114px。它们只属于当前文案；新标题先以字面目标排，再测宽度，不能用相同font-size冒充中英等高。若文字明确要一行，先匹配适合的字宽、字号、合理字距；不能偷删词或横向压扁汉字。

## 平台避让按真实截图测量

先区分用户看的页面：信息流封面上的账号/点赞叠层，与详情页独立标题区未必是同一布局。只模拟用户给的目标页，不能用一个截图声称所有小红书界面都安全。

从截图量出卡片图像区域，再量头像、账号、心形、数字、播放标的矩形或更精确轮廓。记录截图尺寸、图像区域、显示方式及裁切；不要把截图白边、说明、手机状态栏算进封面。若封面和卡片比例不同，先确认完整显示还是居中裁切，再映射；不能直接拉伸后检查。

本次580×772参考卡片样例区域是：头像`[27,682,92,747]`、账号约`[112,700,365,731]`、爱心`[408,696,452,734]`、点赞`[462,703,550,728]`。账号与数字是模拟内容，长度变化时区域也会变。这些测量不是平台常量。

在近似等比、无额外裁切时：`canvas_x = ref_x × W/ref_W`，`canvas_y = ref_y × H/ref_H`。若平台只显示原海报的裁切框 `[cx0,cy0,cx1,cy1]`，先把UI框逆映射成原海报坐标：`canvas_x = cx0 + ref_x × (cx1-cx0)/ref_W`，y同理；再令检查配置的 `ui_reference.canvas` 等于最终海报 `canvas`，填入换算后的框。另存原截图、卡片范围、裁切框及映射公式。检查器不推断裁切，不能用“已核实”的布尔值代替真实偏移。

二维比较署名与各UI对象：头像虽从88.34%H开始，但右边仅15.86%W，署名从19.33%W开始，可以互不相交。

当前Photon署名底边89.8%H；样例爱心顶90.16%H、账号顶90.67%H。与爱心仅差7.11px/2000px高（772px高卡片上约2.74px），属于用户要求的紧贴排法，不是新设计的宽裕安全值。新截图或未知裁切应重测并留合适余量，不盲目保留7px。

系列署名对齐可见底边：Scott整组高96px、Photon高66px，底边同为y1796，顶边分别1700和1730。不要为了顶边齐平把短组下移；更不能因电脑变大，将Photon底边从1796移至1866。V13那次移动与爱心发生重叠，是必须阻止的回归。

区分对齐锁和安全上限：精确复现采用版时，`signature_bottom_ratio` 是双向容差的固定目标，向上移也会提示偏离；本轮明确允许署名在安全区内调整时，用 `signature_bottom_max_ratio` 表达最深底边，向上可以、向下越界不可以，并继续检查真实UI相交。不能为了满足对齐锁强行移回不合适的位置，也不能为通过检查而删除全部约束。

## 布局检查器

`scripts/layout_guard.py` 用标准库读取几何配置，不渲染图片、不访问平台。检查画外、组件互相相交、平台UI相交、标题可见间距和署名底边。填入实际图层边界，以下仅供结构及当前案例复核：

```json
{
  "canvas": [1500, 2000],
  "elements": [
    { "id": "title1", "role": "title", "bbox": [88, 110, 1059, 299] },
    { "id": "title2", "role": "title", "bbox": [86, 360, 1384, 494] },
    { "id": "title3", "role": "title", "bbox": [90, 555, 1394, 650] },
    { "id": "signature", "role": "signature", "bbox": [290, 1730, 1422, 1796] }
  ],
  "ui_reference": {
    "canvas": [580, 772],
    "zones": [
      { "id": "avatar", "bbox": [27, 682, 92, 747] },
      { "id": "account", "bbox": [112, 700, 365, 731] },
      { "id": "heart", "bbox": [408, 696, 452, 734] },
      { "id": "likes", "bbox": [462, 703, 550, 728] }
    ]
  },
  "constraints": {
    "equal_title_gaps_tolerance_px": 2,
    "signature_bottom_ratio": 0.898,
    "signature_bottom_tolerance_px": 2
  }
}
```

```bash
python3 scripts/layout_guard.py layout.json --output layout-report.json
```

示例中的 `signature_bottom_ratio` 用于严格复现；仅检查安全上限时，将其及目标容差替换为 `"signature_bottom_max_ratio": 0.898`，数值仍需按本次截图确定。比例差超过1%时检查器拒绝直接缩放；`mapping_verified:true`不能绕过。存在裁切时，无论比例差多小，都先按上文预映射UI框再输入。检查器不能证明alpha轮廓、文字内容、自然抠图、实际App状态或所有设备均安全；通过后仍看叠加核对图。

## 自然背景与发布图

上部本来干净，就直接在照片上排深色字，不叠厚白牌。下半身接原照，局部虚化时留住裤腿、衣袖和椅子的明暗体积。Logo跨深浅背景可按完整词分色，不按任意像素把一个字切成两色；不要用大矩形背景解决整行对比度。

平台叠层是核对工具，发布文件不能有头像、账号、点赞、播放、圆角或说明文字。用户只要poster就交干净PNG/JPG；核对图单独标“模拟”，账号和数字注明示意，按需展示。文字颜色微改且安全位置像素不变时，复用已核验映射，不反复重做全部mock。
