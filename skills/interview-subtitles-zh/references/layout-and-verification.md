# 版式计算与交付验证

## 方向与实际显示尺寸

以最终显示后的宽高为准，先读取视频编码尺寸、rotation、SAR/DAR、帧率和时长。带旋转标签的素材不能直接用编码width/height判横竖；非方形像素需先按显示比例归一化。只改字幕不改变播放速度，不把新节目1.2×默认再次乘到现有成片。

| 方向         | 比例（宽:高） | 示例尺寸  |
| ------------ | ------------- | --------- |
| 常见横版     | 16:9          | 1920×1080 |
| 本次双语横版 | 4:3           | 1920×1440 |
| 竖版         | 3:4           | 1080×1440 |
| 常见竖屏     | 9:16          | 1080×1920 |

补边和裁切是不同选择。默认以contain保留双人和现有图文；用户明确要求满幅裁切时先核对人物与文字安全区，再采用可审阅的构图，不将裁切伪装成比例转换。背景可沿用已批准的黑色或虚化样式；不要因改中文就重新装饰整个视频。

## 根据英文确定中文位置

设等比缩放因子`s=min(canvasW/sourceW, canvasH/sourceH)`，画面居中。英文源框映射到输出后，`ChineseTop = EnglishBottom + gap`。保守量英文底板和字形的最大边界，不只看短句或字体基线。不存在可移动字幕层的烧录英文只能随主画面整体变换，不能当成独立文字层移动。

辅助脚本使用标准库，从相邻preset读取默认样式，仅输出JSON计划，不修改视频：

```bash
python3 <skill-dir>/scripts/plan_layout.py \
  --source 1920 1080 --canvas 1920 1440 \
  --english-box 0 911 1920 995
```

该例得到完整画面`[0,180,1920,1080]`、英文y`1091–1175`、中文y`1184–1258`。`--english-box`为源画面实测值，不能所有项目都填此例。输出的完整Logo/名牌/人物碰撞仍须实际看帧。

明确需要竖版、中文放在画面之外时：

```bash
python3 <skill-dir>/scripts/plan_layout.py \
  --source 1920 1080 --canvas 1080 1440 \
  --english-box 0 911 1920 995 --zh-placement below-picture
```

此算法示例是主画面容器1080×608、y=416，中文y约1029；不是曾使用的旧shortform y=1044预设，也不是新确认的固定竖版样式。若项目已有1044等批准值，保留该版参数。等比内容尺寸可能有小数，脚本同时给出精确区域和偶数像素容器；渲染保持统一缩放比例，补舍入边缘，不将内容压扁来凑偶数。

默认字号、间距和卡宽按画布宽度/预设宽度缩放；实际字体与像素宽度仍须测量。脚本只检查几何放得下，不能认证手机可读性、遮挡、翻译或同步。所有cue共用固定位置；超宽时改语义分段，不按cue缩字号。需要整体提高字号时，更新项目参数并重验所有cue。

## 现有英文与可编辑双语

| 输入                     | 处理                                                             |
| ------------------------ | ---------------------------------------------------------------- |
| 已烧录一行英文           | 保留原图文；仅新增下方中文，复用已核对时间轴                     |
| 可编辑英文字幕轨         | 在同一配置中规划双语两行，先英文后中文，按当前原句与时间边界输出 |
| 只有英文原声，无可靠字幕 | 先从最终音轨取得转写和词时，核对术语/说话人后翻译                |
| 已有双语版，仅改画幅     | 沿用正确文字和同步，重新检查几何，不再叠一套中文字幕             |

每条语义单元保存`id/start/end/en/zh`和英文来源。时间坐标属于当前输出视频；源原片、编辑参考和当前视频有变化时记录映射，不因为文件名相近就复用。翻译整体句意后按可读、自然的语义拆分；单词级词时只用于必要的拆分和对齐，不逐词直译。

中文短句与原英文cue一一对应时，双语SRT直接输出英文一行、中文一行。若中文跨相邻cue保持同一句，视觉持续显示、避免闪烁；若中文需要更细的cue，按两种语言边界并集合成不重叠事件。不要仅为了凑相同cue数量删字或错误延时。

## 字体、背景与安全区

本期preset为STHeiti Medium 48px、白字、黑色alpha170/255（66.7%），直角底板高74px、左右padding28px、最大宽1640px，参数以1920宽为基准。只分发配置，不复制系统字体；运行时验证字体存在且覆盖所有需要的汉字与标点。换操作系统需指定可用且有许可的中文字体并重新测量，不静默换字体。

底板随实际文字宽度居中，顶部与高度固定。两侧安全边至少是`(canvasW-maxCardW)/2`，还需避让目标播放器UI。名字卡、章节标题、图表/Logo与字幕不能互盖；已有视频元素已烧录时优先调整新增层，不能擦掉重要资料来放中文。

## 验证与输出

复用相邻访谈skill中的SRT检查器，例中的字体和几何来自本期preset：

```bash
python3 <interview-skill-dir>/scripts/validate_timed_srt.py chinese.srt \
  --video output.mp4 --max-lines 1 --end-tolerance 0.034 \
  --font '/System/Library/Fonts/STHeiti Medium.ttc' \
  --font-size 48 --padding-x 28 --max-card-width 1640
python3 <interview-skill-dir>/scripts/validate_timed_srt.py bilingual.srt \
  --video output.mp4 --max-lines 2 --end-tolerance 0.034
```

`0.034`是30fps近一帧容差示例，其他帧率按实际设置；不借容差故意让字幕越过结尾。检查器只检最大行数，所以另逐条确认双语恰好两行、顺序正确、没有空翻译；各语言用自己的字体量宽。SRT是文本与时间交付，精确位置/字形/底色以真实导出帧为准。

至少查看开头、中段、结尾、最宽字幕、切换说话人、姓名条、章节和全屏资料的代表帧；变更处前后查帧。结合真实发声检查字幕进出，文字宽度检查不证明音画同步。新编码的完整视频做全片解码；保留输入音频时核对数据或包hash、首尾时间和最后一句，允许容器差异但不丢包。重新编码音频时不能要求二进制相同，应检查时长、同步与听感。

交付MP4、中文SRT、双语SRT与项目预设，记录实际输入/输出hash、尺寸、帧率、音轨处理和验证覆盖。不要将字幕制作扩展成重新删剪、变速、改音乐或自动插入中文封面。
