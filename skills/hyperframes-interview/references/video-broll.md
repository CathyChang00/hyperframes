# 视频 B-roll 选段与合入

用户提供公司 launch、产品演示、街访、活动视频或指定社媒视频，要求放入已有访谈时读取。以当前批准访谈为底，只改变相关画面覆盖；既有原声、音乐、字幕、章节与倍率继续受保护。本文不要求重新转写或重建整片。

## 先看实际视频，再决定用途

登记每一个用户指定文件或链接。短链接保留原链接，并记录解析后的原帖；公司主页的视频列表是查找入口，不能用同公司的另一条视频代替用户特别指定的一条而声称完成。已有本地资产可复用，先核对来源与文件身份。

查看源视频的时长、画幅、帧率和音轨，再看全片概览与候选段实际画面。文件名、帖子摘要或“launch video”标签不能证明里面有产品 UI。按可见内容选择用途：

| 素材内容                   | 合适用途                         | 不应暗示                                       |
| -------------------------- | -------------------------------- | ---------------------------------------------- |
| 实际界面、操作与结果       | 解释产品怎么用、一次交互如何完成 | 旧 demo 等于当前已上线版本，演示等于效果证明   |
| 版画、抽象动画、品牌故事   | 承接教育理念、产品愿景或相关话题 | 概念图就是实际课堂、校园、已收购资产或真实功能 |
| 街访、行走、骑行、活动现场 | 给当前话题提供人物和场景信息     | 无声口型与采访是同步机位，别段表情是现场反应   |

只记录本次选段需要的来源和语义边界，不给画面额外添加免责声明。来源表区分“公司公开演示”“品牌概念画面”“静音画面拼接”；具体功能、交易、头衔仍按对应证据核实。

## 以完整过程选长度

Cathy 提供或指定的视频每段可至 15 秒，静态全屏新闻、截图和图表仍是 4 秒；其他项目采用本轮配置。分类看来源与展示任务，不只看扩展名：为阅读一张截图而加滚动、缩放并导成 MP4，仍是静态资料；公司完整发布视频中的叙事、版画或品牌动画可按视频选段，不因个别镜头停留、平移或画面呈插画风格就退回 4 秒。数值与检查方式见[资料限时](revision-workflow.md#资料限时与时序的机械检查)。

先找有意义的开始和结束，再看是否在上限内。产品片优先保留“发起操作 → 处理/反馈 → 可见结果”，例如学习目标到课程生成、提出疑问到补充练习、启动环境到应用跑起来；不要刚出现结果就切走。街景和品牌片以动作或场景段落收束，避免出点只闪出下一镜头几帧。检查源边界前后，而不只看每隔几秒截取的概览。

15 秒是允许的最大长度，不是默认时长或最低配额。去掉没有信息的等待、重复输入、白场与冗余，但不要把 UI 正在聚焦、变淡或反馈的有效过程误当空白。过长时选择能独立理解的较短过程，或明确剪成视觉组合；不靠冻帧、重复帧、慢放或无关画面凑长。帧率转换所需的正常重复/丢帧与故意延长停留分开记录。

将候选区间绑定到当前回答的具体句子。延长画面不等于延长全片，也不自动覆盖之前保护的主持人提问、姓名条或章节。已有视频窗口要换长时，记录旧、新覆盖区间；从干净底片重建，或确保新覆盖完整取代旧窗口，防止两端漏出旧素材。

## 声音、倍率与画面文字分开处理

视频 B-roll 默认静音，导入时排除其全部音频流，包含 launch 配乐、旁白和双声道音轨。保留当前已批准的访谈对白与背景音乐；不能因为找到更早的干净底片就换回无配乐版本。只有用户明确要求引用资料原声时，才把它作为单独的编辑任务安排；静音承诺以实际导出的音轨为准。

B-roll 默认原速 1×，其 source 时间与访谈的 1.2×／已批准 1.3× 独立映射；音乐也不继承访谈倍率。区分素材本来已变速、工程播放速率与播放器速率。已有有效运动的视频不再强加静态资料的滚屏。

源视频自带字幕、口号和对话 UI，与节目的单行采访字幕是两层。避免同时叠两套不同口播字幕；先调整等比画幅、位置或选择更干净的源区间，必要时只裁去不承载必要信息的装饰字幕。不能为去字切掉脸、手势、产品结果或关键 UI，也不以涂掉限定词改变宣传内容。产品界面的输入、反馈和结果不是口癖字幕，应保持可读，给采访字幕留空间。

保留源片的原生比例、已批准颜色与有意留边，不能为铺满画面盲目拉伸或裁掉内容。若 crop、去白底或重构图已烘焙进派生素材，工程不要再执行一次；记录 `crop_baked_in` 及实际裁切参数。Cathy 水印和节目字幕位于独立固定层，覆盖资料期间继续可见。以真实导出帧检查关键 UI 和人物动作极值，不仅检查容器尺寸。

## 原片、派生文件、成片三层可回查

连续源段只需记录原始资产身份、源入出点、播放速率和成片区间。只有发生跨段拼接或预处理时才增加派生映射，不为每段建立无用副本：

```text
用户文件/原链接 → canonical 原帖、作者、原始资产 SHA
连续 source ranges / 各段 fps 或源 PTS → 派生区间与派生资产 SHA
crop 是否已烘焙 / source playback rate → 最终 [in_frame, out_frame)
source audio discarded / 选段用途 → 实际导出检查
```

变帧率源用实际 PTS 定位，不把名义 fps 的帧号当精确源时间。派生文件从 0 秒开始不意味着原帖也从 0 秒开始。对外《资料出现时间与来源》写原片各个真实区间；派生 0 秒区间只作工程调用说明，并标“静音画面拼接”，不能冒充连续引语或采访的同步机位。原文件与派生文件都保留身份，裁切和末尾取帧须能沿映射追溯。

这些视频映射使用项目现有 EDL 或素材 manifest 保存并核对。`interview_project.py` 目前检查的是分类限时、与原声的关联时序和证据绑定，不自动校验 B-roll 源区间、派生映射、裁切或是否混入了素材声音；它的 `checked` 不能代替这些工程检查与实际导出审阅。

## 局部验证与交付

复用[局部修订](podcast-production.md#局部修订与验证复用)和[导出边界检查](revision-workflow.md#滚动与配乐修订的证据)。检查每段前、首、中、末、后一帧，跨源拼接另查内部接点；动作、快速转换或文本出现时按风险加看局部播放，不把几张静帧当成已完整看过整段。帧边界有争议时从已知起点解码后选精确帧序号，不能凭快速 seek 的邻帧判定漏帧。

只改画面时，复用音轨需核对数据与时间戳；素材静音、现有配乐保留和字幕不变是分开的检查。更新实际渲染与完整来源表，保留未改的资料记录、原帖、章节和字幕；不能只交本轮新增清单覆盖全片来源。按用户要的完整视频或局部预览交付，不额外设确认关卡，也不因更新 skill 而自动重导已经批准的节目。
