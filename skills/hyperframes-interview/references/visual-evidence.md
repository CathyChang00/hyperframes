# 画面、字幕与社媒证据

在内容阶段规划事件/产品资料，以及用户要求三机位、特写、平衡构图、减少单人长镜头、补 Twitter/X 图文视频、突出浏览量、调整字幕或添加个人水印时读取。

Cathy 个人 16:9 项目先读取 [Cathy 固定样式](cathy-style.md)：下文通用排版和停留时长示例不覆盖她的单行字幕、固定水印，以及静态全屏 4 秒／指定视频 15 秒的分类上限。

## 在内容阶段建立资料计划

整理 transcript 的章节、问题与答案时，同步标记观众需要看到的具体事件、产品操作、合作宣布、文章、人物关系和传播成绩。先把材料需求写入内容地图，再查原帖、确认可用资产，最后决定画面覆盖；不要等对白细剪完才用图片装饰长单人镜头。只改既有封面或名牌时，复用有效计划，不重启无关研究。

每个计划项关联稳定的原句/内容单元 ID，保留原片时间，成片入出点待剪辑方案明确后填写。最小规划为：

```text
内容单元 / 连续原话 / 原片时间
谈话事件或产品 / 需要呈现的具体信息
候选原帖 URL / 作者与 handle / 发帖日期 / 事件日期
相关指标及观察日期 / 目前是嘉宾自述还是已核实原帖数字
可用图片或视频 / 本地资产与来源证据 / 可截取的动作或关键句
叙事作用 / 不能证明的内容 / 预计覆盖位置 / 查找与使用状态
```

状态应能区分“待查、已找到但未核实、已核实、资产可用、已排入、已在导出确认、未使用及原因”，不能把已找到链接当成已切入视频。与 [项目配置](revision-workflow.md)中的 `materials` 关联；原帖未找到或资产不能使用时，记录缺口，继续可独立完成的剪辑，不拿别场活动、另一人的帖子或无关照片顶替。

资料是否值得用，取决于它能否让观众看到当前论点的证据、操作、结果或上下文。先安排章节中的关键事件，再检查连续单人镜头是否缺少信息变化；不按固定插图频率、总秒数或“多放”的数量机械填满。用户指定两个时间点的两组照片或两场活动时，分别建项，不能重复一组交差。

例如讨论 Hermes 与 Photon 合作时，优先找该合作原帖；讨论 ABG CMO 时，区分文章/观点原帖和实际提到的组照；游艇与 go-kart 是两个独立事件。这些是 Photon 的映射例子，不是下一期的必备资料。

## 景别与构图

先看各机位的代表帧，再定义双人、主持人、嘉宾和特写。两机位已够用时不为数量硬塞第三机位；第三机位用于有价值的提问、反应、手势或遮挡跳切，保持同一时间的真实动作与表情。

用发言的功能选择画面，不让嘉宾单人镜头成为整段默认。主持人开启话题、关键提问或追问时，安排主持人可见的单人或清楚的双人镜头；嘉宾回答以嘉宾为主；互动、有效反应与关系变化可用同一时刻的双人或反应镜头。短暂反应切镜可以穿插，不要求逐字跟拍说话者，但不能让一整段关键提问始终只看见未发言的嘉宾。Speaker 归属先按已核实逐字稿和现场信息确认，不能因当前画面是谁就把台词归给谁。

长答案按观点转换、具体例子、重要判断或情绪/手势变化安排近景、较宽景别或资料，而非每隔固定秒数切一次。短而完整的一句话可以保持镜头，避免句内无理由来回切换。重组或微删后的跳切可用同步备用机位、适度 punch-in 或相关资料承接，但声音与语义接点先成立，换镜头不能掩盖重复词、错接句或缺尾音。只切画面时保持同一主音轨，具体约束见[制作参考](podcast-production.md#画面机位与主收音分开选择)。

真正的特写要改变景别，突出面部和情绪；只切到一张仍很宽的单人画面不算。优先从高分辨率原片裁切，检查最终清晰度、头顶与下巴、重要手势、另一人的胳膊/肘部和半个人体侵入。不要为了裁掉肘部又切掉说话人的脸。

构图检查覆盖镜头入点、出点与转头/手势等动作极值，不能用一张静态代表帧证明整段都不穿帮；发现肘部侵入、裁头或切点异常后再逐帧定位。用户要求三机位时登记第三机位实际使用的位置，只有“提供三路素材”不代表必须使用三路；是否使用仍按本轮明确要求及素材价值决定。

审阅镜头计划时，优先检查所有关键主持人问题和最长的连续单人答案：前者能否辨认提问者，后者的景别变化是否服务内容。没有固定最大单镜头时长，不为达到镜头数量打断自然表达。反应镜头必须来自相应时刻，不用别段的点头、笑或皱眉伪造回应。

双人镜头按两人的视觉重量、外侧留白、座位与视线平衡，不能让主持人一侧无功能地空出大块空间。姓名条配对应人物的单人镜头或清楚的双人镜头，不在别人的单人画面下介绍另一人。

用户觉得俯拍、显得佝偻时，优先选更接近平视的源机位，再调整裁切、头部位置和水平线。裁切不能真实改变拍摄高度，不声称已经把高机位变成真正平视；透视微调须检查脸和身体是否变形，不能未经授权重造人物。

## 让资料跟着谈话走

根据前述资料计划，把已核实且可用的资产绑定到实际内容窗口：`成片话题/原话 → 具体事件、产品或观点 → 原始来源 → 图片/视频 → 插入位置 → 能说明什么/不能说明什么`。产品合作、争议文章、活动、反馈等出现时，优先用该事件本身的资料；资料不只集中在开头。正文重剪或变速后从原句/内容单元重新映射，不能沿用失效的旧版秒数。

用户说画面“干”或单人镜头过长时，补充有信息的窗口：原帖关键句、合作宣布、产品操作、活动现场、不同组照、相关反馈。视频和静图可混用；不把所有静图排除，也不让一条 demo 长时间占据开场。没有匹配资料时，用同步主持人反应、双人镜头或有意义的特写承接，不靠无关图片填满画面。

每个窗口只承担一个可读的信息点。demo 保留发起操作、过程与结果，删无信息等待和重复画面；活动视频保留能说明现场规模/互动的动作。图片按阅读量停留，不能一闪而过。Cathy 全屏静态资料最多 4 秒，用户提供或指定的视频素材可至 15 秒；淡入淡出计入，变速后按类型重新计算。实际长度由内容完整性决定，不先把每段硬切成 4 秒，也不强凑 15 秒。公司 launch、产品 demo、街访与派生片段使用[视频 B-roll 选段与合入](video-broll.md)，不强制每隔固定秒数插入资料。

缩短作为 B-roll 的 demo，通常只改变画面覆盖窗口，采访主音轨继续；不能顺手删掉下方问答或移动后文时间轴。只有用户同时要求内容压缩时，才另行调整叙事时长并更新所有映射。

用户指定多个时间点、两组不同照片或不同活动时逐项登记覆盖，不把同一张图重复当两组，也不拿同一公司的另一场活动代替当前事件。涉及负面观点时，不把无关人物照片放上去暗示其涉事。

谈话明确提到影视、书籍、人物或具体产品时，可按原话出现的位置补对应海报、封面、照片或界面。先区分同名作品、地点和公司，例如提到 Silicon Valley 地区不等于在谈 HBO 剧集。优先使用用户指定图，缺少时再找可靠来源；入出点绑定实际句子，不凭相近章节时间猜位置。画面保留片名与重要人物脸，不暗示原话没有的合作或背书；Cathy 的全屏补图同样受限时与滚动规则约束。

### 按信息任务选资料，避免每次提品牌都放同一个 Logo

先确定这一句要让观众认出对象、看到事件、理解机制，还是理解数据与关系，再选资料：

| 当前信息任务                       | 优先画面                                       | 需要避免的替代                                         |
| ---------------------------------- | ---------------------------------------------- | ------------------------------------------------------ |
| 认出公司、产品或人物               | 当前批准的 Logo、产品标志或人物照片            | 提到具体人物却只给公司 Logo；同名公司/考试/产品混用    |
| 看到收购、办学、发布或合作这件事   | 对应事件的原报道、公告、原帖或现场图           | 用普通 Logo 冒充事件证据；用另一年份或另一笔交易的新闻 |
| 理解怎么使用、怎么运作             | 对应界面、操作 demo、流程或原有示意图          | 用品牌名或无关科技画面代替机制                         |
| 理解增长、价格变化、比较或背书关系 | 有来源和时间范围的数据图，或与原话一致的关系图 | 无出处数字、只因视觉好看而拼接的因果/背书              |
| 认出作品或具体案例                 | 用户指定或对应版本的海报、封面、案例素材       | 同名地点误当作品，或用相似但不是当前对象的图           |

核对实体身份后，把用户指定图登记为该实体当前批准资产；不要后续又搜回同名错误素材。需要组合 Logo、关系式、标题内 wordmark 或调整混合深浅字对比时，读取[图形关系与品牌构图](graphic-composition.md)。

人名对应的正式头衔、事件年份和数据口径不能仅从转写猜。若可靠来源与口述不同，内部记录差异，资料使用确实对应的事件和身份，不靠给错年份的新闻或写更高头衔来迁就转写。数据图保留时间区间、单位和来源；“近五年”等相对范围绑定制图时的截止日期，不能画一条示意上涨线冒充真实走势。

再次出现同一资料前，检查它是否承担新功能：新的比较、具体证据、必要回顾或用户明确指定的复现。只有重复识别且此前已足够时，省略这次覆盖；谈话再次提到公司名，不自动触发同一个 Logo。此规则也检查不相邻的重复，不只检查连续两张卡。Cold open 预告、重要回顾与用户指定的多处展示可以保留，注明用途，不把它误解成“全片每种资产只能用一次”。

只为本轮涉及的实体维护轻量用法记录：`实体/来源 ID → 当前批准资产 → 预处理方式 → 使用位置与画面角色 → 每次出现用途 → 替换范围`，与已有资料清单关联，不再手抄另一套成片时间。用户要求“全部替换”时检查所有实际位置，包括标题内 wordmark；只指定两处时保留该范围。重新剪辑后核对旧卡是否仍有信息作用，避免正文重排带来不必要的重复展示。

## 查原帖与指标

先核验人物、公司和 handle 的对应关系。通过可用连接器或浏览器查个人与公司账号，再按产品、合作方、日期、活动关键词和回复链找原帖。搜索摘要只作线索；核原帖作者、日期、媒体内容、完整上下文与可见指标。

每个引用保留最小来源记录：

```text
source_url / author / handle / posted_at / event_date（若不同）
asset_path / asset_type / evidence_path / observed_at
edit_in / edit_out / editorial_purpose / semantic_limits
metric_kind / display_value / exact_value（可见时） / metric_source
```

浏览量与粉丝量要分别取证。帖子的 views 必须属于正在展示的同一原帖，followers 属于对应主页；点赞、播放、曝光和浏览量不互换。显示值与精确值分开，原页面只有 `1.6M` 时不能凭空生成精确计数；访谈自述也不能冒充截图上的当前数字。记录观察日期，无法核实的值不显示。

当谈话的重点正是传播成绩时，可以放大真实 views/粉丝量，让观众读得到；普通资料帖无需都包装成“爆款”。指标、日期、身份与原帖内容不可互相拼接成一条伪造帖子。

## 资料卡保持简单

Cathy 的短 X 内容直接展示真实原帖截图，保留截图内可见的头像、姓名、完整 handle、原帖日期/时间和 views；这些原生信息已经足够，不再外加日期、标题、摘要、脚注或重复署名，也不 paraphrase 原帖。优先调整截图裁边与显示尺寸，保持原文清晰。原图中没有的时间或指标不补写，不拿另一时间、另一帖子或主页的数据拼成原帖界面；缺口只记在内部来源记录中。

长截图优先保可读宽度并使用下节的滚动视窗，原生作者信息、正文和已有指标可依次出现。不要把跨段拼句、改写或删除限定条件后的文字当作截图。信息过密时选有完整意思和必要语境的连续原文；只有确实无法直接展示或用户明确要求时，才做忠实于原文且标为 `原文摘录` 的编辑摘录，不默认归纳为自拟标题或摘要。用户指定整张图时保留其内容范围，优化视窗和停留；仍难读则说明取舍，不能静默缩成窄条、改写或延长。Cathy 的全屏截图和摘录仍不超过 4 秒。

屏幕不重复标注与内部留存出处分开处理。工程索引和 `资料出现时间与来源` 继续保存原帖 URL、作者/handle、可核实的发帖日期/时间、观察日期、真实指标证据、本地截图及实际成片入出点；缺少字段记为未取得，不能伪造。完整链接和核验说明留在来源表，不再加到原帖截图上做脚注；用户或素材授权另有明确的可见署名要求时遵守。

视频 B-roll 默认丢弃素材自带音轨，沿用当前批准的采访对白与配乐；用户明确要引用资料原声时才单独安排。源字幕与节目字幕的避让、独立倍率和源时间映射见[视频 B-roll](video-broll.md)。

被排除的品牌要检查对白、字幕、name card、片尾与引用截图等所有观众可见/可听表面；技术来源索引保留真实出处。资料卡署名、人物姓名标签和个人水印用途不同，不合并为同一模板。

## 资料滚动与长截图视窗

Cathy 的全屏静态资料默认带轻微向下浏览感，内容向上移动；其他项目按当前要求。只移动资料内容层，画布背景、字幕和右上角水印保持固定。全屏已有有效运动的视频无需再滚动，角落 Logo 和章节标题也不自动继承。短网页、海报和图表可先尝试 1080p 下约 40–60px 的缓慢位移，再按实际文字、脸部和数据位置调整。固定 overscan 可用于避免露边，但不能用动画 zoom 代替滚动，或为遮边裁掉关键内容。

长截图先定显示宽度，再定视窗和浏览路径：至少匹配本期已批准的同类原帖宽度，有空间可更宽；没有参考时可从画布宽度约 75% 起调。检查的是原帖内容的实际可见宽度，不是外层容器的 `width: 100%`。不能用整张 `contain` 将高图缩成窄长条。将超高内容裁在固定视窗内，通过上移浏览；视窗避让水印与字幕，不让原生作者或重要文字被遮住。

允许起屏和结束短暂静止，让作者、开头原文和结尾信息可读。头像与 handle 可先出现，正文、配图和原图已有的日期/views 随滚动出现，不要求所有原生信息始终同屏，也不在画面外重新写一套作者、日期或摘要。首尾 hold、淡入淡出均计入 Cathy 的 4 秒上限；信息太多时选择语境完整的连续片段，不能靠高速扫完整页或延时解决。

在项目中记录原图路径与 SHA、视窗位置/尺寸、图层显示尺寸、滚动起止偏移、首尾 hold 和最终帧区间。检查实际导出的首、中、末帧和窗口前后边界：宽度达到参考、滚动方向正确、关键原文依次可见、固定图层不跟着动。hold 内重复帧是预期行为，不以“每帧 hash 都不同”当动画通过条件。边界与验证复用见[修订工作流](revision-workflow.md#滚动与配乐修订的证据)。

## 姓名标签

Cathy 正片介绍人物时使用姓名条；teaser 默认无姓名条。正文姓名条只用两行，不带 `Host`、`Guest` 或额外身份眉题。第一行完整姓名；嘉宾有已确认职务时可用 `<Company> <Role> ｜<Full Name>`。第二行是 `Twitter @完整handle`，保留本轮确认的拼写、大小写和分隔符。职位未知时只用姓名，不猜 CEO、CMO 或雇主；账号未确认则先核验，不能拼造 handle。用户要求的 exact copy 优先。

Photon 最终批准内容为：

```text
Cathy Chang
Twitter @cathychang00

Photon CMO ｜Julie Chen
Twitter @0xJuliechen
```

这两块分别出现，不把四行叠成一张卡。Cathy 姓名卡的小写账号与常驻水印 `Twitter @CathyChang00` 是分别批准的显示文案，不用一次全局替换统一大小写。不要把完整名字截成 Cathy，或把旧雇主加回来。

姓名行较大且加粗，账号行较小；两行左对齐，底板包住内容，删掉角色眉题后同时回收多余高度，不留空白第三行。Photon 的 1920×1080 版本使用 Inter 52px/700 与 32px/400、约 22px×32px 内边距和直角深色底板；这些数值只作该画幅起点，按长名字、脸部位置与字幕安全区调整。名牌底板不必与半透明字幕底板相同。

介绍 Cathy 时给 Cathy 或清楚的双人镜头；介绍 Julie 时给 Julie 或清楚的双人镜头。卡片不遮脸、不碰字幕，较长的职位姓名仍完整可读，不为塞一行把账号缩成小字。只改标签时保留批准的时段、淡入淡出、声音、字幕与封面；同步工程变量、composition 和真正烧录的图集/MP4，查看两人各自的实际导出帧。

## Cathy 个人水印

Cathy 的个人项目默认使用原文 `Twitter @CathyChang00` 作为个人标记，保留空格、`@` 和大小写。它不是雇主标识、嘉宾署名或片尾 CTA；不替代各人的姓名条与资料来源。此偏好不适用于其他用户，也不自动套到公司或客户项目；用户本轮明确要求的文案、位置或关闭水印优先。

Cathy 16:9 的确切位置、尺寸、颜色和 alpha 使用[固定预设](cathy-style.md)，复用已批准透明资产，不自行猜色或重缩放。在画布右上角安全区放独立的全片覆盖层，从首帧到最后一帧的每一帧持续显示，包含 cold open、采访、图片、视频 B-roll、章节卡与片尾。保持静态、低调但清晰可读，不带入场/退场动画或音效，不随镜头和场景切换消失，也不能被全屏资料层或转场盖住。

按实际画幅给水印保留独立空间，与字幕（Cathy 预设为单行）、姓名条、原帖账号、浏览量和章节文字分开；避免遮挡人物与演示操作。可以用轻描边、阴影或小面积半透明底保证明暗画面上的对比，不把水印做成另一块抢眼标题。其他资料与右上角水印冲突时，调整资料和片内信息的布局以避让，不临时移动或隐藏水印，也不靠某一帧碰巧留白。

同时更新工程预览和实际导出，把水印烧入最终视频；单改封面、HTML 文案、字幕文件或导出元数据不算完成。仅添加水印时保留已批准的时长、帧率、音频内容与音画同步。先确认全片覆盖层的时段、可见性与层级覆盖所有帧，再查看最终导出的首帧、中段、最后一帧，以及图片/视频 B-roll、章节切换和最宽字幕的代表帧，抽样核验全文可读、无碰撞；首中末仅是抽样检查，不代表水印只在这几处出现，也不能单凭抽样声称已逐帧验证。核对 `ffprobe` 的时长、帧率和音轨信息。

## 字幕与资料的共同安全区

字幕语言和画幅取当前要求；英文原声字幕不能擅自润色为说话人未说过的句子，用户确认的纠错保留依据。语义分组、稳定锚点、零重叠适用于不同版式；Cathy 的单行要求优先，长句按真实词级时间分成连续短字幕。其他项目未指定时可最多两行，字号与安全宽度按输出画布实测。

Cathy 使用固定预设中的 Arial 单行白字、直角黑色半透明底；字号、位置、宽度和 alpha 从同一个 JSON 读取，不再从约 60% 的估值开始试。已有项目批准的例外或本轮新参考优先。不要把旧 3:4 中文模板的坐标、40px 字号和实黑底硬搬到 16:9 英文节目。

在放帖子、指标和姓名条之前预留字幕区域。导出实际帧，查看最宽原句、连续分句、名字/账号、指标与背景对比，必要时整体移动资料或卡片；不能依赖“预览看起来有空间”。改文字后同时更新实际烧录 PNG/图集、HTML 与 SRT，避免只改文稿却继续用旧字幕图。
