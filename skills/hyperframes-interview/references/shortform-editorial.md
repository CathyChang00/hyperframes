# 短切片选题、原声叙事与 3:4 版式

用于少数主题、Cathy 4–6分钟切片、粗剪转折及已选3:4版式。长节目用longform；横版封面用[封面工作流](cover-workflow.md)，不套本页坐标。批准内容的小改复用有效审阅。主线确定时建立[资料计划](visual-evidence.md#在内容阶段建立资料计划)；cold open、跨句接点及风险微删用[关键剪口语义检查](podcast-production.md#关键剪口语义检查)。

## 从长访谈收敛成少数视频

### 选题方法

把问题、回答、数据作为evidence pool，不按问题数拆视频。主线未定时给最多6个proposal，列命题、证据链、边界；选定后逐句扫全稿。每条须有可复述结论及机制、案例、边界/结果，人物、产品名或关键词本身不算论据。

给每个细节标起点、机制、变化、案例、结果、例外或组织影响；不能说明作用就放unused pool。B若主要解释A且复用同组证据，应合并；仅在结论和证据均独立时拆开。同一句原声默认只归一条；删除topic后的剩余素材也仅按补强作用回收。

按独占原声先算时长再承诺条数。偏短时沿同一因果链扩大母题；证据只够2–3分钟就标optional short或减少条数，不复用/填弱段硬凑每条5分钟。

### 标题与 chapter

Title写结论、反差或状态变化；Subtitle解释机制；Chapter写观众能理解的论证步骤，不用内部剪辑标签。数字先核验指标、单位、speaker、时间范围，自述标self-reported。

### 3:4 访谈的三层标题

从最终script分别提取身份、最强判断、公共结果，三个发布表面各司其职：

| 位置         | 内容与1080×1440参考值                                                                                                              |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| 顶部身份     | 已核验Logo＋`采访 <Company> <已确认职位> <Name>`；职位未知只写姓名，不默认CEO。顶部虚化区，Logo宽420–560px，文字42–48px，左右≥72px |
| 底部固定判断 | 独立成立的结论/反差/强问题，1–2行、42–46px、宽≤900px；编辑改写不加引号                                                             |
| 平台发布标题 | 按平台包装一个点击理由，可用人物/结果/核验数字，不重复前两层                                                                       |

已有方向直接执行，要求选稿才给候选。用户数、声音数、ARR、下载量等口径不可互换。

### Storytelling paraphrase 与原话

先写 `结果 → 起点/误解 → 动作/机制 → 转折 → payoff`，再找原声。分清 `topic thesis`（判断）、`storytelling paraphrase`（叙事）、`exact transcript evidence`（可搜索原文）、`subtitle correction`（执行建议）；改写可重排综合，不进引号或quote block。

每个excerpt来自连续原声，含speaker、文件/时间码。机器稿保留；原片或用户亲听确认的纠错另存并标来源，不确定标VERIFY，不润色原话。speaker用用户信息、现场字幕或录制说明核对，不凭声纹猜身份；确认前不称CEO quote。

## Cathy 的 4–6 分钟访谈切片

### 全原声优先与开场 Hook

默认交付全原声Paper Script，不写/预留补录VO。开场前2–3个完整信息点先交代具体事件、结果、时间差、人物或反差，再谈定义/履历/框架；标题有数字或事件时，前三句必须直接指向它。

优先 `嘉宾结果 → 原片问题 → 机制回答`，或 `主持人背景问题 → 结果回答`。结果句指代不清先恢复原问题/现场铺垫；对象、结果、对比齐全才直接冷开场。问题必须由紧随回答直接回收，过长从同段连续原声压短，不为露脸保留弱问。允许透明微删并标jump cut，不把跨段拼句称作连续原文。ASR或身份仍不明时VERIFY，或在不破坏主线时删段并说明，不能用新VO补未经证实的故事。

### VO question / POV

`纯POV`是无声屏幕文字，不生成新音频；原片提问可作buffer，不算补录。仅用户明确要VO时写两句、约11–14秒：核心疑问＋具体观察/对比/追问，随即接最短明确答案。问题只负责前1–2组回答、约50–100个英文词内回收，不概括整条5–6分钟或塞进全部chapter。

### 粗剪中的提问 Buffer

以用户指定cut/vX及对应稿为时间轴真值，稿失配或缺失才转写。标相邻段末句、首句和jump cut，先还原不同回答背后的原问题。转场顺序：`原片问题镜头 → 原片铺垫/问题的透明jump cut → 嘉宾过桥句 → 无声chapter card → 明确要求才补录VO`；“不重录/不要VO/只用原片”是硬约束。

只在论证机制变化处插问；同一因果链已有过桥或最后一分钟仍在收束时保持连续，不每刀都插。问题须在随后50–100个英文词内回收；有错误前提就恢复嘉宾纠正，问大答小时补足答案或弃问。指代悬空优先恢复原问题；过长可用无声卡交代指代，再接原片短问。

每个buffer交付 `粗剪插入点｜前后exact line｜原文件/时间码｜原片/无声卡/恢复回答类型｜第一句回收｜增加时长｜新总长`，跨段剪接明示。优先主持人或双人镜头提供视觉换气，无合适画面时原声可覆B-roll，不生成新声。

### 时长估算

文字草案按英文130–150 words/minute估算，加原片问题、停顿和剪口缓冲；非母语/停顿多靠近130，紧凑稿靠近150。有素材后用实际区间及批准倍率核算，仅明确要求补录才计新VO；叙事完整就停。

## 已选 3:4 成片的继续加工

指定vX是时间轴基线，原词、完整词尾与现场声音仍回未剪原片核查；下列尺寸仅用于注明画幅。

### 画布与已有元素

保留批准字幕、name card、chapter title和版式，不重复叠加；本轮要求修正/排除的元素实际改掉。居中公式 `foreground_y + foreground_h / 2 == canvas_h / 2`；1080×1440内完整16:9为 `1080×608, y=416, bottom=1024`。

动态中文字幕放主视频下沿后的虚化区，不贴画布底；一/两行共用顶部锚点，不上下漂移。

### 中文字幕语义分组与样式

本节一/两行规则仅用于未指定单行的单语短片。英文访谈双语版按[中文字幕与转画幅](../../interview-subtitles-zh/SKILL.md)，英文上中文下、每语种一行，不被旧3:4参数覆盖。

用户确认中文是文字真值，ASR只对齐。先按语义分cue：同句因宽度换行仍一cue，独立句/观点/问答/speaker则拆开依次出现；报告原/新cue数及一/两行数。先实测单行，超宽才自然换行、最多两行；旧1080px画布参考安全宽940px，其他画幅按实测边距。

新字幕可从白字、直角、黑底60%不透明度开始，不改已批准实黑底/参考。旧1080×1440中文预设：`Heiti SC 40px, 行距8px, padding14px, y≈1044`，不套16:9英文。动态卡居中，避让姓名牌/指标；渲染前看最宽卡、所有两行cue与专名，用户纠错不能被ASR或烧录字幕改回。

### 逐词音画匹配

1. 最终成片为时间轴真值，中文cue映射所译英文的word-level区间，不沿用宽泛Whisper segment。起点参考preroll0.05秒、end hold0.12秒，按词尾/呼吸调；cue不重叠，真实停顿留白。ASR认出词不证明尾声完整，异常回原片。
2. 逐句校正并报告最大start/end correction，不全轴统一偏移；同segment拆句用词边界，不能按时长比例猜。
3. 运行 `python3 <skill-dir>/scripts/validate_timed_srt.py <srt> --video <final-video>`；时间倒退、重叠、超两行、越片尾或超宽即停导出。
4. `fps=4`联系表初筛口型、原英文字幕、词时，重点查修正、换speaker、问句及片尾；截字/一帧错位须查切点实际帧，0.25秒抽样不作帧级认证。
5. CTA仅按本轮要求/批准方案使用，品牌账号取当前确认值，不从旧项目补入；不截末句，必要时顺延。排除品牌同时检查对白、字幕、姓名条、卡片及资料。

### 提问背景插图

只补当前问题缺失的context，不复述字幕或塞发布长文。信息限 `已核验来源/人物｜一句判断｜最多三个阶段/映射`；职位不推断，阶段卡只写框架，不重复口播里的产品例子。

置于3:4顶部虚化区，不盖人物；近实底深色面板、大白字、单一强调色，避免低对比细字。仅在背景提问时显示，问题完成后退出；导出实际帧按手机/LinkedIn尺寸缩小检查，一眼读不清就重做。

## 产品发布 framing

标题和发布文案解释“产品为何这样设计”，不只列功能，也不把访谈冒充产品发布。

## 已验证的排序模式

排序服从理解依赖和本条证据链；历史项目的选题、删段或Hook不成为下一期默认要求。案例见[Photon复盘](photon-case.md)。
