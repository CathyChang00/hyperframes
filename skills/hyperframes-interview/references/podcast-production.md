# 播客制作与原声完整性

在多机位、收音选择、截词/异响修正、变速或交付成片时读取。具体时长、帧率、采样率和倍率来自本项目；不要复制旧项目的数值或滤镜参数。

## 完整问答与自然口播

完整节目先列 `章节 → 主持人问题 → 保留答案 → 案例/边界`。产品介绍、论题转换、必要追问与纠正前提的问题应在剪辑稿和视频中有对应位置；不能只完成嘉宾正文。逐人清理无效附和、重复起句、嘴瓢、自我修正、填充词，保留有功能的反应与呼吸。

用户希望主持人听起来更自然时，目标是原声表达利落：优先保留一次说完整的版本，安全删除冗余，用同步机位或相关资料遮住跳切。不要把所有 `like / so / actually` 当口癖，也不要通过新配音、口音重塑或改写原句伪造“native”。

用最小记录防止漏改：`片段ID｜speaker｜原文件｜source入/出｜完整原话｜剪辑动作｜输出出现位置`。同一原句在片头和正文出现时，登记重复引用；一次纠错应同步到所有对应画面、声音、字幕及本次交付的在线稿。

## 画面机位与主收音分开选择

1. 先登记每个文件的时长、分辨率、帧率、音频 stream/声道、采样率及起始 PTS；识别分段录制文件，不凭“镜头1/2/3”或文件头判断同步。
2. 抽取同一 reference 时间的对照片段：主持独讲、嘉宾独讲、交叠、安静与用户指出的异常处。核查削波、回声、底噪、串音、响度和可懂度；把实际听审与仪器分析分开记录。
3. 双人镜头可能收音最好，但只是候选。主画面可以换机位，主音轨应保持连续；不要每次切画面就切到该机位的劣质声音。
4. 双领夹或分轨要核验声道归属。按说话人选清楚的通道，保留弱回应与交叠，必要时短交叉淡化；不要把不同距离、不同延迟的多路音频永久等权叠加，或用硬门限切断另一人的回应。
5. 同步映射写清方向，例如 `reference_time = scale × native_file_time + offset`，并标文件、有效区间和代理起点。在开、中、后及跨文件接缝复核波形/口型，确认是否漂移。文件内时间、共用 reference 时间与成片时间必须能互查。

## 截词、漏词与异常声音

当前成片是编辑基线；未剪原始 MP4 是原话和完整声音的调查来源。不要从已剪 master 的下一段取声音来“补尾”。

1. 用户指出一个词不完整时，先把问题点映射回原片，从句前到句后保留宽上下文，再比较可用的原始声道。需要用户自查时，打开对应原文件并定位，给出该文件的分钟/秒数，不能把 reference 或成片时码当原文件时码。
2. ASR、强制对齐、DTW、波形和口型用于定位，不能单独认证词尾完整。零时长 token、低置信边界词尤其要回源；另一个人开始说话或画面嘴闭合，也不代表前一人的尾音已完整保留。
3. 区分录制噪声、坏剪口、处理伪影和播放问题。关门、碰麦等突发声可能覆盖辅音或尾词，不能把整块高能量声音标成“非语音”后删除。
4. 优先寻找同句更干净且可同步的原始录音；否则轻处理并做同源、同响度的前后对照，检查被移除部分是否含语音。不能用固定频段/谐波遮罩或较低 RMS 证明声音更好，也不能因 ASR 仍能认词就认定未损伤人声。
5. 无法消噪又保词时，保留完整原声及现场声，并明确说明；不要截尾掩盖问题，不擅自合成缺词。不具备直接听审能力时提供原速对照，准确报告技术检查范围。
6. 用户亲自听原片确认了原话或噪声原因，记录为 `user_confirmed` 的人类证据，保留机器原稿。执行稿和字幕采用确认内容，不再用 ASR 漏词反驳；文字确认不授权生成声音，也不等于助手听过。

补尾后先确认源区间完整，再处理画面与字幕：从原文件恢复真实尾部，边缘淡化不得吞掉有意义音节；所有重复引用一起调整。保留处理前的音轨和修复范围，便于对比或回退。

## 变速与时间映射

只有用户授权变速时才应用。片头、正文或指定段落分别记录倍率，并从原速素材独立生成；片头已按 1.3×处理后再套 1.2×会变成 1.56×，不能这样实现“片头1.3、正文1.2”。这些数字只是示例。

使用保音调的变速方式，实测输出长度与收尾。用整数输出帧、项目的有理帧率和半开区间 `[in, out)` 记录切点；音频按累计边界换算样本并声明舍入方式，避免每段取整造成长片漂移。不得为了满足预定帧数静默裁掉非静音词尾；若需静音补齐或末帧保持，记录新增长度和位置。

修改前建立 `旧输出区间 → 新输出区间 → 原文件时间 → 倍率` 映射。更新字幕、章节、B-roll、姓名条、问题、播放器总时长与所有重复引用。预览底片/音轨若已经烘焙倍率，主播放器设为 1×；素材卡内部速度也要检查，避免二次加速。

## 交付与验证

先制作能暴露本轮风险的短预览：例如完整尾词与下一句接点、两人姓名条、最宽字幕和一处资料卡。用户已授权整片时，该预览用于内部检查，不自动变成新的等待批准节点。

稳定候选封装后检查实际输出：

| 检查对象       | 必要证据                                                                                  |
| -------------- | ----------------------------------------------------------------------------------------- |
| 文件与完整性   | 实际路径、时长、分辨率、帧率、音视频流、旋转/色彩信息；最终 MP4 完整音视频解码无报错      |
| 内容与边界     | 开头、最后一句与末帧、变更点前后、章节接点、关键问题、修复原句的每个出现位置              |
| 字幕与画面     | 实际导出帧；字幕不截字、不越界，名字与画面人物匹配，资料卡可读且真实出现                  |
| 音频修复或变速 | 最终压缩音轨与冻结原声 master 的局部偏移、句尾/接点和首尾长度；全片相似度不能代替局部核查 |
| 版本           | 最终视频、master、EDL/plan 的文件身份或 SHA；检查后再改媒体，需要对受影响范围重新验证     |

技术检查通过不等于听感通过：报告实际检查范围、是否有人听审、仍保留的现场声音。已有验证只有在相应输入和时间映射未变时才可复用；仅改画面后，若要复用音频验证，应核对音频数据与时间信息确实未变并关联新 MP4。

按用户任务交付本地全片 MP4、最终 SRT 和有用的短预览，工程保留来源、机位/收音映射、版本与资料索引。使用新版本文件，保留上一版；回读实际文件后才说“已保存到本地”。播放器预览、渲染中状态、打开命令或工具零错误都不能替代导出文件和画面检查。最终说明变化、关键限制与可打开的文件即可，不把内部审计日志铺给用户。
