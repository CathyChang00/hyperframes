# HyperFrames Interview Longform

Cathy 个人 16:9 项目遵循[固定样式预设](../hyperframes-interview/references/cathy-style.md)；当前要求及批准的局部例外优先。制作与收音见[播客制作参考](../hyperframes-interview/references/podcast-production.md)，资料选取见[视觉参考](../hyperframes-interview/references/visual-evidence.md)及[视频 B-roll](../hyperframes-interview/references/video-broll.md)。用户要视频时按主技能渲染交付，Paper Edit 只是执行依据。

## 硬边界

1. 先区分硬上限、期望长度、无硬目标，并记录批准倍率。估计时长不当硬指标；无硬目标时由内容决定长度，不另套固定分钟数。完整版定稿后才按 [LinkedIn 子技能](../hyperframes-interview-linkedin-cut/SKILL.md)另出短版。
2. 首次建立节目或重选正文必须通读完整 transcript。批准版本的局部修改先核对素材身份与覆盖范围，复用仍有效的审阅、内容地图和剪口检查，只更新受影响项。
3. 默认只用现场原声，不新增 VO 或跨语境拼出新判断。`exact transcript` 与删词后的执行台词分列，每段含 speaker、source timestamp、可搜索原句；自述数字与归因保留 self-reported 边界。
4. 用户必留主题、明确恢复的故事/问题是内容约束。Paper Edit 从第一句写到最后一句，覆盖全部保留段，不能用摘要、代表片段或占位说明代替。
5. 保留机器稿；用户确认的姓名、品牌及亲听原片后的纠错另存并标来源，用于执行稿与字幕，不能据此合成缺词或润色原声。

## 工作流

### 1. 建立可核查逐字稿

音视频先用 [hyperframes-media](../hyperframes-media/SKILL.md)取得带时间戳与 speaker 的稿；已有稿核对素材版本及时间码基准。人名、产品、数字、中英混说回原片核验，记录机器识别、原片对照或用户听审的证据类型；无法确认标 `VERIFY` / `[听不清]`，不能把机器检查称为人工听审。

无 speaker 标签可暂标 `Host（推断）` / `Guest（推断）`，列出待确认切换点。稿件已去口癖或只有段落时间码时，只统计可见词并标 `transcript-based count`；声音口癖及句内切点另需音频或词级时间。

### 2. 还原整期内容地图

将全文拆为句子级单元，标 `KEEP`（论证所需）、`MICRO-CUT`（句内安全微删）、`CUT`、`MOVE`（完整单元移动）、`HOLD`（备选）、`VERIFY`。

先还原问题线与证据链，再聚合分散话题：

```text
观众问题｜主回答 source｜互补信息及作用｜重复版本｜必要问句/上下文｜拟放置位置
```

同关键词不等于同问题；选一次最完整主回答，再补机制、不同证据或边界，不首尾拼接两个完整答案。按理解依赖排序：产品定义先于依赖它的策略，解释动机的经历贴近问题；原顺序清楚就保留。cold open 可先给冲突，正文仍补前提。

逐章检查问题有直接回答、证据足够、指代与转折成立。Cathy 建立节目与主持人身份的简短自我介绍默认保留，与嘉宾长履历或无功能片头分别判断。在此阶段建立[资料计划](../hyperframes-interview/references/visual-evidence.md#在内容阶段建立资料计划)：原句→事件/原帖→可用资产→覆盖窗口，无资料不填无关画面。

### 3. 逐人建立口癖清单

按本次原稿统计每位 speaker 的填充词、重复起句、自我修正、同义复述和附和，记录 `总出现 / 建议删除 / 建议保留 / 原因`。Cathy 优先检查[个人口癖与提问规则](../hyperframes-interview/references/cathy-style.md#cathy-的口癖与提问精剪)中的叠加起手式、句中 `like / uh`、连接词重启和重复问法，不把候选词一律删除。

以下保留：有实际语义的 `like / right / 其实`；删除会改变语法、态度或因果的词；有功能的犹豫、幽默、情绪、呼吸；音频粘连或口型难以自然处理的内容。微删必须同时满足语义、语气、语法及音画连续性。

主持人重复解释同一问题时留最直接且能引出答案的一次问法；嘉宾自我修正优先保留同一上下文中的完整正确说法，无法自然剪开就保留必要修正，不合成缺词。

### 4. 按信息价值压缩结构

删减顺序：制作闲聊/重复介绍 → 无效附和、重复问题与空转 → 重复起句和同义复述 → 被其他保留段完整覆盖的观点 → 跑题、过长背景与无回报铺垫 → 作用相同的例证 → 不影响结论的补充。删除重复内容时指出承接它的保留段。

以问题、答案、机制/证据、边界是否连贯判断，不强套章节顺序。个人动机、市场规模、经济性、竞争对照、结果或反例可能互补，不按“第二个例子”机械删。幽默与故事可承担解释选择、落地或收束功能；保留其必要铺垫和回应，必要限定不为节奏让路。

### 5. 保护必留主题

```text
必留主题/内容单元｜结论或作用｜source range｜预计时长｜是否完整｜缺失证据｜用户确认/恢复依据
```

全部覆盖后定稿。同一原声默认只服务一个正文 chapter；cold open 可预告性复用，登记全部位置，修词、补尾、换声道时同步更新。

用户“加回”后，将 source range 与作用写入执行稿和覆盖表。可清理其中冗余，整项再删须有覆盖该保留要求的新指令，不能让旧时长偏好或旧剪辑表撤销它。补回前说明补哪个证据缺口、放哪里、增加多少最终时长；不从 unused 素材随意补长段。

### 6. 核算当前目标时长

以同一主参考时间轴计算，不叠加多机位：原速唯一保留量＝保留 source ranges 的并集；真正删除＝原片未保留区间，移动不算删除，重复引用只在唯一量中计一次。

最终播放时长按每次实际出现的区间和批准倍率求和，再计独立片头/图卡及转场重叠；覆盖对白的资料不加时长。分别报告原片、原速唯一保留、真正删除、变速缩短、teaser 重用和最终实测，保留率注明分母，不能把“原片减成片”全称作删减。

不足不补口癖或跑题，只从 HOLD 恢复论证缺口；放宽上限也不必加长。超限先去冗余与弱例证，额外变速须获授权；片头/正文不同倍率均从原速生成，不叠乘。片头或句尾变化后重算字幕、资料、章节和总长。

### 7. 回答“相对原片删了什么”

分开维护原片累计账与本轮版本差异。累计账覆盖原片全部区间的保留、微删、移动、删除或待核验去向；未用 HOLD 计入未保留清单，恢复后同步撤销删除标记。每项写原片时码、可定位原话、理由、承接段；B-roll 缩短与下方问答删除分别登记。不能只报分钟数，或拿上一版差异代替相对原片的删减。

## Paper Edit 交付格式

```text
标题 / 源素材与 transcript 版本 / 比较基准
原片 / 原速唯一保留 / 真正删除 / 批准倍率
teaser 重用及新增独立时段 / 目标及预计时长 / 保留率与口径

【必留主题覆盖】主题｜作用｜source range｜时长｜状态
【删剪概览】口癖、重复与自我修正、重复观点、跑题/制作对话：数量及节省时长
【Speaker 口癖审计】speaker｜词/模式｜总数｜删/留数｜保留原因

【Chapter N｜观众能理解的问题或主题】功能｜成片时间
Speaker｜source timestamp
exact transcript：可回搜的连续原文
去口癖后的剪辑参考台词：保留原词及语序，写出删后全部台词
剪辑动作：KEEP / MICRO-CUT / MOVE、具体删词、遮挡方式
风险：语义、口型、粘连、ASR、数字核验

【完整删除清单】source timestamp｜speaker｜exact removed transcript｜理由/承接段｜节省｜风险
【HOLD】source timestamp｜speaker｜exact transcript｜补强作用｜增加时长
```

连续删除区间可合并但不得漏段；微删列具体词，整段保留足以搜索的原文。可附 `~~删除原词~~` 标记版，但清洁执行稿必须完整，不能写“仅删除下表词语”替代。

## 剪辑连续性

保留有功能的问题、追问、转折与自然停顿；不因答案勉强独立就全删主持人。仅移动完整回答/论证单元；句内微删可用双机位、反应、punch-in 或相关 B-roll 遮挡。

按最终顺序检查代词、时间、因果、身份，以及删后残留的半个例子、悬空引子与无落点转折：恢复收束或整体去掉依赖单元。换机位不能重播起句，意外重叠先修主音轨。区分原本的强调与剪辑引入的重复。

cold open、跨句拼接及风险微删执行[关键剪口语义检查](../hyperframes-interview/references/podcast-production.md#关键剪口语义检查)：并列剪前上下文、删词、剪后实播原词，记录 reviewer 和实际版本证据；机器检查不替代语义判断。

## 飞书、Notion 与 Google Doc 顺序

默认按上方模板顺序组织，最后附素材与版本说明。同页含选定 teaser 时，将完整 teaser 放在页面标题后、longform 前；用户指定顺序优先。

## 交付前否决检查

未覆盖全文/必留项、未核算当前上限与倍率、缺原文/人物/时间码、微删无具体词与位置、累计账无法定位、剪后完整台词缺失、语义或自然语气受损、问答/视频/字幕错配、片头正文重复引用未同步修正，任一项存在即不交付。局部视觉修订只验证受影响范围。
