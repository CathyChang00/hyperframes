# HyperFrames Interview Longform

Cathy 个人 16:9 项目使用[固定样式预设](../hyperframes-interview/references/cathy-style.md)：单行字幕、固定标题与水印、新建节目全片 1.2×、全屏资料≤4秒；teaser 无姓名条，正片介绍保留姓名条。当前要求及项目批准的局部例外优先。

把长访谈剪成符合本轮目标的完整节目，不自动拆成若干短视频，不把编辑改写冒充现场原话。保留关键主持人问题、现场原声和人物语气，所有剪辑决定可回原片核查。用户要求视频时按主技能完成渲染和交付，Paper Edit 是执行依据，不是成片替代品；制作与收音读取 [播客制作参考](../hyperframes-interview/references/podcast-production.md)，画面资料读取 [视觉参考](../hyperframes-interview/references/visual-evidence.md)。

以下全稿扫描、口癖统计与完整删剪清单用于首次建立节目或重新选择正文内容。已有批准全片只改封面、姓名标签、字幕样式或局部已确认原句时，复用有效的全文审阅与内容地图，仅更新受影响项目，不重启选题、全片转写或要求用户重复审批。

## 硬边界

1. 区分硬时长上限、期望长度和无硬目标，并记录可否变速。用户说“20 分钟只是估计，15 或 30 都可以”时，先合并话题、去重复，再由完整内容决定长度；不另套 25 分钟锚点，也不以删掉多少分钟证明剪得好。明确的硬上限仍需满足。
2. 首次建立或重新选择正文内容时完整扫描原始 transcript，再写精剪稿；不能只看摘要、提纲或金句。延续批准版本时先核对已有全稿审阅的素材身份与覆盖范围，范围未变则复用。
3. 用户指定的必留主题及确认恢复的具体故事、案例、问题是内容约束。先建立覆盖表，再删其他内容；不能只保留主题名，却为了时长把已确认的内容单元再次删掉。
4. 默认只使用现场原声。不要把 editorial paraphrase 写进嘉宾台词，也不要新增主持人 VO，除非用户明确要求补录。
5. `exact transcript` 与 `去口癖后的剪辑参考台词` 必须分开。每个保留段和删除段都标 speaker、source timestamp 与可搜索原句。
6. 口癖不是看到词就删。只有删除后语义、语气、语法和口型连续性都成立时才标为安全微删。
7. 数字、增长、客户反馈和归因若来自嘉宾自述，保留 self-reported 边界；精剪不能把个人判断升级成事实。
8. Paper Edit 必须从第一句保留原声写到最后一句，包含所有最终保留段，不得只交代表性 excerpt、chapter outline 或内容摘要。
9. 用户确认的姓名、品牌和亲听原片后的原话用于执行稿与字幕；保留机器原稿并标记纠正来源，不让 ASR 漏词推翻用户确认，也不能凭文字确认合成、润色或伪造原声。

## 工作流

### 1. 建立可核查逐字稿

1. 输入只有音视频时，先读取并使用 [hyperframes-media](../hyperframes-media/SKILL.md) 生成带时间戳和 speaker 的 transcript；输入已有逐字稿时先核对其时间码基准与素材版本。
2. 对人名、公司名、产品名、数字和中英混说回原片核验。记录机器识别、原片对照或用户听审等证据类型；不能直接听时不宣称人工听审，无法确认的词标 `[听不清]` 或 `VERIFY`。
3. 保留机器转写原文副本，不在唯一一份 transcript 上直接覆盖修改。
4. transcript 没有 speaker 标签时，可根据连续问答暂标 `Host（推断）` / `Guest（推断）`，但必须列出待人工确认的 speaker 切换点，不能把推断写成事实。
5. transcript 若已经清理过 `um / uh / 嗯 / 呃` 或只有段落级时间码，只统计文本中实际可见的口癖，并注明 `transcript-based count`；未被 ASR 记录的声音口癖和句内精确切点仍需回听音频或取得 word-level timestamps。

### 2. 还原整期内容地图

把全文拆成句子级最小单元，并分别标注：

- `KEEP`：主结论、机制、关键案例、必要上下文、边界或收束。
- `MICRO-CUT`：可从句内安全删除的口癖、重复起句、自我修正或无意义连接词。
- `CUT`：整句或整段删除，包括重复观点、跑题、制作对话和低信息追问。
- `MOVE`：整段移动到更清楚的 chapter；不要跨语境拼半句话。
- `HOLD`：有价值但受时长限制的备选段。
- `VERIFY`：时间码、专有名词、数字或语义仍需核验。

先写出原片的问题线与证据链。用户要求合并分散话题时，按观众在问什么、回答承担什么作用聚合全部出现位置，先归位再删重复；同一个品牌或行业关键词不代表同一问题。每组记录 `观众问题｜主回答 source｜互补信息及作用｜重复版本｜必要问句/上下文｜拟放置位置`。选一次最完整的主回答，再接补充机制、不同证据或边界，不把两个完整答案机械首尾相连。

按理解依赖安排正文：观众需先知道产品是什么，再理解为什么采取某项策略；只陈列个人履历的部分可后置，解释产品动机或选择的经历贴近对应问题。移动背景不等于删除背景，热话题也不自动成为正文第一章。冷开场可以先给强冲突，其后正文仍补齐理解前提；这不是每期固定的章节顺序。原片本来清楚时保留顺序，不为重排而重排。

逐章检查问题是否被直接回答、证据是否足够、指代与转折是否成立；不得只交嘉宾正文。Cathy 正文中建立节目与主持人身份的简短自我介绍默认保留，精简重复措辞即可；它与嘉宾长履历、无功能片头镜头分别判断，不能因删了一个就删掉全部“介绍”。

在这一步同步建立 [资料计划](../hyperframes-interview/references/visual-evidence.md#在内容阶段建立资料计划)：把事件、合作、文章、活动与传播成绩关联到原句、具体原帖和可用资产，再安排覆盖窗口。不要等正文细剪完才搜图片，也不因某章没有资料而填入无关画面。

### 3. 逐人建立口癖清单

Cathy 的主持段按[个人口癖精剪规则](../hyperframes-interview/references/cathy-style.md#cathy-的口癖与提问精剪)重点复核连续及填充性的 `like`，连同其他实际出现的习惯一起精简；该偏好适用于 teaser 和正文，不因“个人风格”默认保留无信息口癖。

必须根据这一次原始 transcript 统计每位 speaker 的真实口癖，不只套通用词表。候选通常包括：

- 中文填充词：`嗯`、`啊`、`呃`、`然后`、`就是`、`其实`、`对`、`那个`、`怎么说`。
- 英文填充词：`um`、`uh`、`like`、`you know`、`I mean`、`basically`、`actually`、`right`、`so`。
- 结构性冗余：重复起句、半句重来、自我修正、连续同义复述、主持人的 `yeah / 对对对 / exactly` 式附和。

对每个候选记录 `总出现次数 / 建议删除次数 / 建议保留次数 / 保留原因`。以下情况必须保留：

1. 词语承担真实语义，例如 `like` 表示喜欢或举例、`right` 表示方向、`其实` 建立必要反差。
2. 删除会让句子语法断裂、态度变强、因果改变或显得不自然。
3. 语气词承担停顿、犹豫、幽默、情绪或人物个性，且没有拖慢叙事。
4. 音频粘连或口型无法自然处理，微删成本高于收益。

主持人绕着同一问题反复解释时，保留一次最完整、直接指向答案的核心问法，删重复铺垫、同义解释和收尾重问；不能把“精简问题”做成删除主持人。嘉宾嘴瓢或自我修正时，优先保留同一上下文中一次完整的正确说法；无法自然剪开就保留必要修正，不合成缺词。

### 4. 按信息价值压缩结构

按以下顺序删减，不从核心论据开始砍：

1. 录制前后闲聊、设备确认、重复介绍和制作对话。
2. 无效附和、重复问题、回答前的空转和不影响意思的口癖。
3. 同一 speaker 的重复起句、自我修正与连续同义复述。
4. 已被另一保留版本完整覆盖、没有信息增量的观点或案例；删除前能指出由哪一段承担其信息。
5. 与主线无关的支线、过长背景和没有 payoff 的故事。
6. 同一论点中承担相同作用、没有增量的重复例证；个人动机、市场规模、经济性、竞争对照、结果或反例可能互补，不按“第二、第三例”机械删减。
7. 最后才压缩有价值但不影响结论成立的补充和边界。

章节应让问题、答案、必要机制/证据和边界连得起来，顺序依实际对话和理解前提决定，不强制每章套“结论→机制→证据→边界”。一个具体数字、交易案例或个人经历若补足不同问题，就不是因为同属一个主题而重复；若只是再次陈述同样结论，才考虑去掉。

幽默、反应和个人故事也按作用判断：能让观点落地、解释选择或给前文一个有效收束的笑话可以保留，不因没有新增事实就删掉。保留必要的铺垫与回应，不孤立留下包袱，也不为“像故事”保留无回报的长铺垫。必要限定条件不能为节奏让路。

### 5. 保护必留主题

先建立以下矩阵，所有主题都覆盖后才能定稿：

```text
必留主题/内容单元｜核心结论或作用｜保留的 source range｜预计时长｜是否完整成立｜缺失证据｜用户确认/恢复依据
```

同一原声默认只服务一个正文 chapter。主题间重复时保留信息更完整的一处；已选 cold open 可以预告性复用正文原声，记录所有出现位置，修词、补尾或换声道时一起更新。

用户说“这段可以留”“这些都加回”后，将对应 source range 和内容作用记为受保护的恢复项，更新当前执行稿与覆盖表；后续沿用旧剪辑表不能再次丢失。允许清理其中口癖和无信息重复，进一步拿掉该内容单元须有覆盖该保留要求的新指令，不能用旧的时长偏好擅自撤销。补回内容时先检查当前片子的证据缺口，说明它补哪个问题、放在哪里、增加多少最终时长；不是为了凑时长从未用素材里随意补长段。

### 6. 核算当前目标时长

1. 以同一主参考时间轴计算原片时长，不叠加多机位的重复录制。原速唯一保留长度按保留 source ranges 的并集计算，真正删除长度按原片未保留区间计算；移动片段不算删除，teaser 复用正文只在唯一保留量中计一次。
2. 时长不足不补回口癖、重复或跑题；只在论证不完整时从 HOLD 池恢复必要问题、例证和边界。用户放宽上限时，以内容完整性决定是否加回。
3. 超过用户上限时先去冗余和弱例证；需要额外改变语速时取得用户对此的授权。已授权片头与正文不同倍率时分别从原速音画生成，不叠乘速度。
4. 最终播放时长按每次实际出现的 source range 和批准倍率求和，再计新增的独立片头/图卡时段及转场重叠；覆盖在对白上的资料不额外增加时长。将原片、原速唯一保留、真正删除、变速缩短、teaser 重复引用与最终实测长度分开报告，不能用“原片减成片”冒充删掉的内容长度。保留率写清分母与口径。
5. 修改片头或句尾后重算字幕、资料、章节与总时长，详见制作参考。无硬目标时，最终长度是内容选择的结果，不是唯一验收指标。

### 7. 回答“相对原片删了什么”

累计原片删剪账与上一版到本版的差异分开。前者让原片每个区间可查到保留、微删、移动、删除或待核验去向，明确比较的是哪份完整素材；后者只说明本轮新增、恢复、移动或删除。用户问相对原片的删减时，不交上一轮差异充数。阶段稿的 HOLD 是候选，成片中未用的部分仍应列入累计未保留清单。

对用户有意义的删除清单写出原片时码、具体原话/内容、理由以及是否有保留段承接；不要只报删了多少分钟或几个口癖。恢复内容后更新累计账，避免它仍被旧表标成删除；缩短 B-roll 展示与删除下方问答分别登记。

## Paper Edit 交付格式

```text
标题：<Long Podcast Script V1>
源素材：<文件 / 链接 / transcript 版本>
原片时长：XX:XX
原速唯一保留 / 真正删除：XX:XX / XX:XX
批准倍率 / teaser 复用及新增独立时段：<分开列出>
目标成片：XX:XX
预计保留率：XX%（<口径>）
比较基准：<原片累计账；若另附本轮版本差异，标明前后版本>

【必留主题覆盖】
主题｜核心结论｜source range｜预计时长｜状态

【删剪概览】
口癖微删：X 处 / 约 X:XX
重复与自我修正：X 处 / 约 X:XX
重复观点：X 段 / 约 X:XX
跑题与制作对话：X 段 / 约 X:XX

【Speaker 口癖审计】
Speaker｜口癖｜总出现｜建议删除｜建议保留｜保留原因

【Chapter 1｜观众能理解的短问题或主题】
本章功能：结论 / 机制 / 案例 / 边界
预计成片：XX:XX–XX:XX

Speaker｜source timestamp
exact transcript：<可回搜的连续原文>
去口癖后的剪辑参考台词：<写出删除后实际连续播放的完整台词；只删原声中可剪内容，不补写新句>
剪辑动作：KEEP / MICRO-CUT / MOVE；写清删词、jump cut、双机位或 B-roll 遮挡
风险：语义、口型、音频粘连、ASR 或数字核验

【完整删除清单】
source timestamp｜speaker｜exact removed transcript｜删除原因｜预计节省｜jump-cut 风险

【HOLD 备选池】
source timestamp｜speaker｜exact transcript｜可补强什么｜预计增加时长
```

删除清单不能只写“去口癖”或“重复”。句内微删要列出删掉的具体词，整段删除要保留足以搜索定位的连续原文；连续删除区间可以合并成一项，但不得省略未列出的删除段。

`去口癖后的剪辑参考台词` 必须是真正的执行稿：保留原词和原语序，写出删词后剩余的全部台词。禁止用“保留 exact transcript，仅删除下表词语”“参考删除清单”或其他占位说明代替。需要让剪辑师同时看到删词位置时，可另加一行 `标记版`，用 `~~删除原词~~` 标出微删，但清洁版仍必须完整提供。

## 剪辑连续性

1. 同一句内删除口癖或重复起句时，优先用双机位切换、反应镜头、轻微 punch-in 或相关 B-roll 遮挡 jump cut。
2. 完整节目保留有功能的问题、追问和转折；可删重复问法、无效附和及整组被淘汰的话题。不要因为答案勉强能独立理解就一律删主持人；确需删问句时检查对象和语境，保留问句时检查答案是否直接回应。
3. 允许移动完整回答或完整论证单元，不把相隔很远的半句话拼成嘉宾没有说过的新判断。
4. 保留自然呼吸、笑声和有功能的停顿。精剪后的目标是紧凑但仍像真实对话，不是逐字无缝连读。
5. 重排后逐章检查代词指向、时间顺序、前后因果和人物身份，避免 `this / that / it / 他 / 这个` 失去指代。

删掉后续内容后，再从最终播放顺序检查前面是否残留半个例子、悬空引子或无落点的转折；恢复必要收束，或整体去掉不再成立的依赖单元，不能仅因每个词都完整就通过。换机位也不能让原声回退、重播同一次起句；相邻 source range 意外重叠时先修主音轨，再处理画面遮挡。原本有意义的重复强调与剪辑引入的重复要分开。

对 cold open、跨句拼接和有风险微删使用 [关键剪口语义检查](../hyperframes-interview/references/podcast-production.md#关键剪口语义检查)，并列剪前连续上下文、删词和剪后实播原词，记录 reviewer 与证据；机器检查只能提示风险和缺证据，不能替代语义判断。已审查且内容、时间映射未变的区间可复用结果。

## 飞书、Notion 与 Google Doc 顺序

无用户指定格式时，执行稿可按以下顺序组织：页面标题 → 时长与保留率 → 必留主题覆盖 → 删剪概览 → Speaker 口癖审计 → 完整 Longform Paper Edit → 完整删除清单 → HOLD 备选池 → 素材与版本说明。若同一页面还包含 teaser，teaser 仍放在页面标题后的最前面，longform 内容随后。

## 交付前否决检查

出现任一情况就不能交付：

1. 没有可复用或本轮完成的全稿审阅，或必留主题缺少 source range；仅做批准版本的视觉局部修订时，不重复要求内容审阅。
2. 超出用户当前时长上限，或没有逐段核算保留片段与批准倍率后的时长。
