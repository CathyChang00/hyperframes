# HyperFrames Interview Teaser

Cathy 16:9 遵循[固定样式预设](../hyperframes-interview/references/cathy-style.md)，当前要求及批准例外优先；teaser 无姓名条，正文介绍保留姓名条。[视频 B-roll](../hyperframes-interview/references/video-broll.md)的素材上限不替代本片节奏与总长要求。

cold open 以强主张引入长片；独立 teaser 自身须可理解、有落点。用户给定范围优先。完整节目中的已选 teaser 默认合入同一成片开头，独立工作文件不能代替完整节目。

## 本轮交付先后

选项已定且用户要求先做 teaser，就先完成该条原声、剪口、字幕和样式，不改交跨章节视觉样片。明确先看静帧才停在静帧；“放上去”即执行批准设计。要求先选候选时不修改主成片；获授权完成后不重复确认。

先检查每句是否承担冲突、原因、证据或落点，去掉无信息铺垫和可安全删除的起手式，检查删后连接词与指代。大字动效不能补救原声逻辑。应用批准效果到全篇时迁移设计规则，不照搬 teaser 的标签、密度或长度；合并后检查接点仅播一次、无多余空镜/静音，以实际帧数更新正文字幕、章节、资料表和交付链接。

## 长片 cold open

1. 无指定长度时先找 15–20 秒的完整开场，不套独立 teaser 的 30–60 秒，也不为凑秒数截词或补弱句。对象/关键词尽量在前 3–5 秒出现，前 10 秒仍泛泛铺垫就重选起点。
2. 按用户命题选有对象、有态度的完整原句，保留量词、限定和观察边界；不能把“很多”剪成“所有”。偏长时清理冗余，单句太短时恢复必要一层意思，不靠未批准倍速或截尾解决。
3. 按用户要求提供文字、原片定位或独立预览；要三个就给三个有实质区别的候选，列原话、文件/时间范围、批准倍率下长度、吸引力及推荐。明确要完整候选时才逐条制作。
4. 保留尾词、辅音和自然收束；可复用正文原句，但登记两处，纠词、补尾、修声同步更新。音频与倍率见[制作参考](../hyperframes-interview/references/podcast-production.md)。

语境卡只补缺失信息，不重复已清楚的原声；不自动加刺耳转场音，不复活用户删除的标签。[默认封面](../hyperframes-interview/references/cover-workflow.md#默认封面不等于片头视频)不占 cold open 时长。

选原声同时建立[资料计划](../hyperframes-interview/references/visual-evidence.md#在内容阶段建立资料计划)，不先锁长 demo 再硬塞。替换前对候选及正文接点做[关键剪口语义检查](../hyperframes-interview/references/podcast-production.md#关键剪口语义检查)：保留上下文与实播原词，核对主语、限定、否定、因果、指代，记录 reviewer 和实际版本；文本通过不证明声音完整。

以下骨架供独立 teaser；cold open 按长度取适用检查。

## 硬边界

一条只讲一个 topic；选三个 topic 就交三条，明确要求 montage 才混剪。独立 teaser 未指定时参考 30–60 秒，常见 40–50 秒，论证结束就停。默认只用现场原声，不新增 VO；可用无声标题/数字/语境卡补最少背景。

仅在同一 topic 的 evidence pool 内重排，不跨主题借句、改变因果或合成新话。每段标 speaker、source timestamp、连续可搜索原文；exact transcript 与删口癖稿分开，标明微型 jump cut。标题的编辑判断不能冒充原话；嘉宾自述数字、购买、增长和归因标 self-reported。

## 先建立留存骨架

先用用户当前语言写叙事，再匹配原声；逐点写清听觉信息与画面任务：

| 时间     | 必须完成                                                  |
| -------- | --------------------------------------------------------- |
| 0–3 秒   | 结果、数字、冲突或反常识判断，topic 立刻清楚              |
| 0–5 秒   | 补人物、对象或业务结果；`it / this / that` 的指代同帧补全 |
| 5–10 秒  | 反差、代价、原因或未解问题，给继续看的理由                |
| 10–15 秒 | 第一轮 payoff、硬细节或转折；人物战绩转向“为什么/怎么做”  |
| 15–30 秒 | 机制、案例或数据，不复述开头                              |
| 30–60 秒 | payoff、判断、边界或反转，自身成立                        |

主持人问题进前 10 秒须同时满足：本身含具体事件/数字/冲突，嘉宾随后 5 秒内直接回答，且比嘉宾结果原声更抓人。放在 10–20 秒的问题应将战绩或断言转成公共问题，压为同段连续原声，约 30 秒前接直接答案；不为露脸保留弱问题。

## 选择 Hook

未指定数量时可内部比较 3–5 个，按本轮命题选择业务结果、反直觉冲突、判断、案例 payoff 或强问题，不固定数字优先。对 `前三秒清晰度 / 自洽性 / 证据密度 / 新鲜度 / 可剪性` 各评 0–2 分，清晰度为 0 直接淘汰。

多个完整 teaser 中，主 teaser 优先论点单一、公共价值明确、视觉证据充分且有断言结尾；人物 teaser 可从战绩开场，但 15–30 秒转入可复用方法/判断。给推荐，保留用户选择。

## 原声重排规则

优先结果句开场，再补原因/背景。句内删除填充词、重复起句或自我修正时须语义、语气、语法及音频可剪，可用 B-roll、双机位或 punch-in 遮挡。屏幕文案只补最少语境，静音前三秒也应看见 topic 与关键结果，不能替代逻辑。

## 时长核算

有素材按 source ranges、实际停顿与批准倍率计算；只有文字时用英文约 130–150 words/minute 暂估并标注。独立标题卡、反应及转场单独计时，最终以输出实测为准。

## 交付格式

```text
Teaser Title / Subtitle / 核心命题 / 预计秒数

【成片时间｜结果、补对象、反差、机制/证据或 payoff】
Speaker｜原文件与 source timestamp
exact transcript：连续原文
去口癖后的剪辑参考台词：删后全部原词
屏幕文案与画面任务
剪辑动作：具体删词、jump cut、B-roll/数字卡、风险
```

按实际叙事重复区块，时间段可合并；另回答 3 秒给什么、5 秒补什么、10 秒为何继续、15 秒是否完成首轮 payoff/转向。

## 交付前否决检查

前三秒寒暄/动画/泛泛介绍、5 秒仍不知对象或冲突、10 秒无继续看的理由、15 秒仍堆背景、多 topic 混杂、指代悬空、量词/自述被升级、缺 speaker/时间码/连续原文，任一项存在即重写；不能只把长片平均缩短。

## 飞书、Notion 与 Google Doc 位置

更新长版 Script 时，仅将最终选中的完整 teaser 放在页面标题后、链接/素材说明/长版稿前。删除旧位置，回读标题、首句与结尾均只出现一次，并保留 5/10/15 秒检查。
